# AI Agent Configuration for Fuel50

> Configuration for AI-assisted development of Fuel50 microservices.

## 🤖 Agent Capabilities

✅ **Can Help With**:
- Adding new microservices following reactive patterns
- Creating REST endpoints with Mono/Flux
- Writing R2DBC repositories
- Implementing service-to-service communication
- Writing integration tests with Testcontainers
- Mapping entities to DTOs

❌ **Not Recommended**:
- Blocking operations or synchronous code
- Breaking the microservice boundary
- Mixing reactive and sync code

## 🧠 Project-Specific Knowledge

### Core Concepts
- **Mono<T>**: 0-1 values, like `Optional<T>`
- **Flux<T>**: 0+ values, like `Stream<T>`
- **ReactiveCrudRepository**: Auto CRUD methods, async
- **R2DBC**: Async, non-blocking database access
- **@TransactionalhScope**: Reactive transaction handling

### Common Patterns
- Return `Mono<Entity>` from repository, map to `Mono<DTO>`
- Use `.flatMap()` to chain Mono operations
- Use `.collectList()` to convert `Flux` to `Mono<List>`
- Handle `Mono.empty()` for not found cases

### Known Gotchas
1. **Mono must be subscribed** - Controller framework does this
2. **Never call `.block()`** - This defeats async benefits
3. **DTOs separate from entities** - Domain models in entities, API in DTOs
4. **Service clients in common-clients** - Not duplicated per service
